# Design: "Replace the line" for a rule-based fix in Studio (N8)

Status: proposal, no code. The code waits for acceptance. Same family as `studio-insert-before-step.md`, which it reuses (the kept text of the run, the step anchor, the editor-race rules).

## What exists, and what is missing
- A failed `see "X"` or `tap "X"` gets rule rows from `studio/triage.go`. Today the only rule fix is `wait until "X" appears`, which is an **insertion** (`studio-insert-before-step.md`). The rules never produce a line that replaces the failed one.
- **Replace the line** already exists, but only on the AI card (`CheckReplaceLine`, `studio/replace_line.go`), for a suggestion a model wrote.
- So "a rule-based fix that replaces the line" has **no source today**. This design defines one that needs no model and no network: the runner already records what was on screen when a step timed out (`runner.VisibleItems`: the texts and keys that fit whole, environment values masked; `FailedSelector.Visible`, set only from the runner's own step-timeout error). Studio does not receive it yet: the step event has no such field.

## The one replacement the rules make (v1)
The failed step is `see "X"` or `tap "X"` with a **text** selector (an id gets no replacement: ids and keys are out of v1), it timed out, and exactly **one** of the visible texts equals X after folding and not byte for byte: both sides NFC, case-folded, edge spaces trimmed and runs of whitespace collapsed to one space. Then the replacement is the same step with that on-screen text: `tap "Sign in"` with `Sign In` on screen becomes `tap "Sign In"`.
- Computed in **Go** from the failed step and the runner's snapshot. The window never supplies, edits or sees an alternative; it gets an id of the step, as the AI card does.
- No match, two or more matches (ambiguous), or a match that is already byte-equal (so the text is there and the failure is something else) give **no replacement**, and no button.
- A visible text is data from the app under test, so it is distrusted: it is used only if it is one plain line (`plainSuggestionLine`: no line break, control, hidden, bidirectional or other-width space character), has no `"` and no backslash (so the quoted form is exactly the text: the check is `strconv.Unquote(`"` + text + `"`) == text`, both directions), carries no masked-environment marker, is at most 40 characters (what `VisibleItems` keeps whole), and differs from X by the folding above only. Anything else: no replacement.
- Out of v1, listed so a reviewer sees they were considered: a unique near match (prefix, contained text, edit distance), key and id replacement, `long press`, `double tap`, `type`, `see` with `any of`, negated steps. Each needs its own evidence of how often it is right; see the open questions.

## Where the text comes from, end to end
1. `runner`: `StepEvent` gets one data field, `Visible VisibleItems`, set on `StepFailed` only when the error is the runner's step-timeout error (the same value `FailedSelector.Visible` takes). Nothing that decides a verdict reads it; the CLI ignores it. A test pins both.
2. `studio`: when a failed step is turned into a `RunStep`, `triageStep` also gets the visible texts and sets `StepTriage.Replacement` (the new quoted text only, never a whole line) and a row reason that names what the screen showed ("the screen shows "Sign In", not "Sign in""). The window shows it as a row with one button.
3. The line that goes into the editor is **built in Go at press time** from the kept text of the run: the original line with only the text between the quotes swapped. The row text is display only.

## The anchor and the checks: `CheckReplaceStep`
A new bound method, pure like `CheckInsertBefore` and `CheckReplaceLine`: `CheckReplaceStep(file, line, openFile, content)` answers `{ok, line, text}` (the new text of that one line) or a one-line reason. It reads nothing from disk and writes nothing. It refuses when:
1. a run is in progress (`a.track.snapshot().Running`) or the run's kept text for the file is not held;
2. the step has `Depth > 0` (a recipe step: its line is a line of the recipe, not of the calling file; the same refusal and reason as Insert before);
3. the open file is not the file the step ran from (`sameFile`);
4. the editor text differs from the kept text of the run after the same normalisation as Insert before (BOM dropped, CRLF and CR become LF): "the file changed since the run: run again";
5. the line is not exactly the failed step: one step starts there (`stepTarget`), with the event's verb and quoted text, as `see`/`tap` with a text selector, and the line holds nothing else (no flags, no second step, **no trailing comment**: a comment would have to be carried, and v1 refuses instead of guessing);
6. the replacement, recomputed here from the run-state step (never from a window argument), is not allowed by the rules above, or equals the text already on the line;
7. the text after the swap does not parse to **exactly the same steps at exactly the same lines** (`stepsOf` and `sameSteps` as Replace the line, the line count is unchanged) with the one selector text changed and the verb, flags and shape (`fixProfile`) kept. The profile check is what "same verb class" means: a `tap` stays a `tap`, a `see` stays a `see`.

## The editor (window)
- The window applies the edit only when the check said ok **and** the editor is still what was checked: at the click it captures the open path, `model.getVersionId()` and the text; after the Go answer it applies only if all three are unchanged (one model, never `setModel`), as Insert before does.
- One edit in **one undo stop** (`pushUndoStop` before and after), replacing the one line; the caret goes to the line. The line ending of the line is kept (the swap does not touch it). **Nothing is saved**: Save stays the person's action. Nothing is run, and no "try it" step: the person looks, then presses Run.
- The button is disabled between `run:started` and `run:finished` (`runGoing`), the handler refuses while running, and Go refuses while the tracker is running (check 1): three independent layers.
- Line count does not change, so the step marks and row line numbers stay valid; the marks of the replaced step are cleared and the row says "edited". After the swap the file differs from the run's text, so every other offer of that run (this one, Insert before, the AI card) refuses with "the file changed since the run: run again" until the next run, the same staleness rule. An **Undo** brings the run's text back and the button works again.
- The row sits where the rule rows are, with its own label so it is never confused with the AI card's **Replace the line** (see the open questions).

## The method and its entry
`CheckReplaceStep` in `studio/bound_methods.json`: category `ui`, callers `window` and `bridge`, `touches` none, `confirm` `none`, `does` "Checks whether the rule-based replacement for a failed step may be put into the editor, and returns the new text of that line; reads Studio's kept text of the last run; changes nothing." Not in the automation method list (the guard test checks it). The guard tests derive `touches` and fail if it reaches a file, the keychain, the network or a device, so "pure" is enforced, not claimed. No AI, no provider, no network. `asks` is not used: nothing here needs a person's answer in Go, the person's press is the answer, and the check changes nothing.

## Tests to write with the code (a mutant per test)
- `runner`: the field is set for a timeout and empty for every other failure and for a pass; the CLI's reports are byte-identical with and without it.
- `triage`: a table of the replacement rule: one fold match gives it; none, two, a byte-equal match, an id selector, a text with a quote, backslash, control, hidden or bidirectional character, a masked marker, a text over 40 characters, and a visible list with `Cut > 0` where the match might be among the cut items (refuse: a cut list cannot prove "exactly one") give none.
- `CheckReplaceStep` table: one case per refusal above (running, no kept text, Depth > 0, another file, a changed file by one character and by an edit above that shifts an identical step, an unsaved edit, a line with a comment, a line with another step, a replacement that fails `Unquote`, a result that parses to different steps or lines) and the accepted case; a mutant per refusal; two identical steps with an edit above must be refused (the wrong-step case); a CRLF, a mixed-endings and a BOM file are accepted after normalisation.
- The guard tests: the entry is present and derived as pure.
- Playwright, no device, a seeded failed run that carries visible texts: the row appears only when the rule gives a replacement; one press swaps the quoted text and one undo restores it, and the button works again; a second press is refused; an edit first (above or on the line) is refused; another open file is refused; a press during a run is refused (disabled) and a press that races the click (the editor changed between the click and the answer) applies nothing; hostile on-screen texts (markup, a quote, a backslash, a bidirectional character) show as text and give no row or an inert one; with the AI card on the same step, after this edit the AI card's **Replace the line** refuses, and the other way round; a CRLF file; marks and counts stay valid; no Save call is made (a recorded route proves it).

## Out of scope
Recipe steps (Depth > 0: needs the real file on the event, a separate change), ids and keys, other verbs, fuzzy matching, running after the edit, saving, any model, any new network call, and anything that changes the runner's verdicts.

## Open questions for the owner
1. **Label.** The AI card's button is already "Replace the line". Recommendation: this row says "Use "Sign In"" (what it does, with the text), so the two are never confused. Alternatively use the same words for both.
2. **Suppress the wait fix when the screen shows the other spelling?** If the screen showed "Sign In" at the timeout, the text is not late, it is spelled differently, and `wait until "Sign in" appears` would time out again. Recommendation: yes, when a replacement exists the rule offers the replacement and not the wait. This changes the Insert before row (its test table gets one more case).
3. **Fold only, or also a unique near match?** v1 is fold-only: the evidence that a person means the on-screen text is as strong as it gets. A unique prefix or edit-distance match would make the offer more often and be wrong more often. Recommendation: v1 fold-only; decide again with the counts of how often the offer appears in real runs.
4. **A Re-run card after the swap?** The line count is unchanged, so the existing Re-run card could be offered as after the AI replace. Recommendation: yes, same rule (`lineCount` unchanged), since the verdict is the proof the replacement was right.
5. **Comments on the line.** v1 refuses a line with a trailing comment. Carrying it is possible (swap only the quoted span); recommendation: ship the refusal, add the carry only if the refusal is seen to be common.

## Further Studio hardening, ranked by value for the effort
Each has a number to hit, so a review can say done or not done.
1. **Windows vet is in no gate.** `scripts/ci-local.sh` builds `./cmd/...` for Windows but never vets `./studio/...`; #825 sat on main unnoticed. Add `GOOS=windows go vet ./studio/...` (and `GOOS=linux`) to `ci-local.sh` and `studio-ci.yml`. Target: 0 packages failing on all three OSes, and a deliberately broken `Setpgid` line in a scratch branch turns the step red. Cost: very small.
2. **Save in place is not atomic.** `WriteFile` truncates and rewrites the person's file; a crash or a full disk mid-write leaves a truncated file (Save-as, the exports and the settings file already write to a temp file and rename). Target: a writer that fails after N bytes leaves the original byte-identical (a test with a failing writer seam, N in {0, 1, half, all-1}); the file mode is kept; a link in the place of the file is still refused. Cost: small.
3. **`WriteFile` can write a `.probe` file under `.git` or any hidden folder inside the workspace, and has no size cap.** Target: a table of 10 hidden or VCS paths (`.git/`, `.hg/`, `.svn/`, `node_modules/` as the person decides) refused with a sentence, and a cap equal to Save-as's 1 MiB or an owner-chosen one; 0 writes under those names in the test. Cost: small; needs the owner to choose the list.
4. **The browser suite has one known load flake** (`ui-03`, a real device listing under load) and the web suite is the gate for the window. Target: 0 failures in 20 consecutive full runs on a loaded machine (a loop in `ci-local`), by answering the device listing by hand in the specs that do not test it. Cost: small.
5. **Recipe steps have no anchor** (`Depth > 0` is refused by Insert before, Replace the line and this design). Add `StepFile` to the step event. Target: Insert before and the new Replace work for a step inside a recipe, with the same table of refusals; the kept text of recipe files is used for the first time. Cost: medium, touches the runner's event.
6. **`studio/frontend/src/main.ts` is 2,637 lines** with the shortcuts, save, record, run, connect and chat in one file; every change in it risks the others (the Save-as, Insert and shortcut work each had to read all of it). Target: no behaviour change, the full web suite unchanged, and the file under 1,800 lines by moving the Save/Save-as, Record and the shortcut handler into their own modules with node tests. Cost: medium, low risk if done one module a PR.
7. **Studio workflows are off (#402, an owner setting) and the scripts replace them locally.** Target (owner): `studio-ci.yml` and the e2e workflows enabled, and `scripts/ci-local.sh` parity checked by a test that the same steps exist in both. Owner action, not mine.
