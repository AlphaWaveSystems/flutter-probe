# Design: "Replace the line" for a rule-based fix in Studio (N8)

Status: proposal, no code. Revised after review (the replacement must be proven to match one widget, the AI card's weaker checks are named with a prerequisite change, and `Visible` is shown to be no new exposure). The code waits for acceptance and comes after the hardening queue (atomic and capped `WriteFile`). Same family as `studio-insert-before-step.md`, which it reuses (the kept text of the run, the step anchor, the editor-race rules).

## What exists, and what is missing
- A failed `see "X"` or `tap "X"` gets rule rows from `studio/triage.go`. Today the only rule fix is `wait until "X" appears`, which is an **insertion** (`studio-insert-before-step.md`). The rules never produce a line that replaces the failed one.
- **Replace the line** already exists, but only on the AI card (`CheckReplaceLine`, `studio/replace_line.go`), for a suggestion a model wrote.
- That existing replace is **weaker** than what this design asks for, and it should not be the model for it. `CheckReplaceLine` has no Running check; `lastFailedStep` (`ai_context.go`) ignores `Depth`, so a failed recipe step's line is taken as a line of the calling file; and its anchor is only "line N has the same text as when the suggestion was asked for", which two identical steps plus an edit above that shifts the second into line N pass (`sameSteps` compares kinds and lines only). A **prerequisite change**, before or with the code of this design and queued right after acceptance: `CheckReplaceLine` gets the Running refusal, the `Depth > 0` refusal and the kept-text anchor (the same checks 1 to 4 below), with a table test and a mutant each. Until then, any claim that "the AI card refuses after this edit" would hold by accident (the line text differs after a swap), not by design; the Playwright list below tests it only after that change.
- So "a rule-based fix that replaces the line" has **no source today**. This design defines one that needs no model and no network: the runner already records what was on screen when a step timed out (`runner.VisibleItems`: the texts and keys that fit whole, environment values masked; `FailedSelector.Visible`, set only from the runner's own step-timeout error). Studio does not receive it yet: the step event has no such field.

## The one replacement the rules make (v1)
The failed step is `see "X"` or `tap "X"` with a **text** selector (an id gets no replacement: ids and keys are out of v1), it timed out, and the snapshot shows exactly one text N that equals X after folding but not byte for byte. The fold is Studio's own and is **intentionally narrower than the agent's loose fold** (`textfold.dart` also folds accents, typographic dashes and apostrophes, and full-width forms): both sides NFC, case-folded, edge spaces trimmed, runs of whitespace collapsed to one space. The two folds are not to be aligned later: a narrower fold offers less, and a wrong offer costs more than a missing one. Then the replacement is the same step with N: `tap "Sign in"` with `Sign In` on screen becomes `tap "Sign In"`.

**The proof that is needed is about the new step, not the old one.** The agent matches a selector text as a **case-sensitive substring** by default (`_textHit`, `_matchesText` in `finder.dart`), and a step acts on the first match in tree order. So "exactly one text is fold-equal to X" proves nothing about what `tap "N"` will hit: with `Sign In` and `Sign In with Google` both on screen, `tap "Sign In"` matches both and taps the first in tree order, which may be the OAuth button; `Delete` against `DELETE` and `DELETE ALL` is the same. The rule therefore also requires:
1. **Exactly one** visible text **contains N as a substring** (case-sensitive, as the agent does by default). That text is N itself. If any other visible text contains N, there is no offer.
2. **The snapshot must be provably complete.** Two things drop texts. The agent stops at a cap (`visibleSummary({int max = 25})`, hard-coded in `finder.dart`, unknown to Go) and reports no cut; and an item over 40 characters is left out of `Texts` by `wholeItems` and only counted in `Cut`, yet it can **contain** N ("Sign In with your email address to continue"). So: **`Cut > 0` means no offer**, and the agent reports `truncated: bool` (true when any list hit the cap or any item was skipped) together with the cap and the count; Go refuses when `truncated` is true **or absent** (an agent that does not say is treated as incomplete: fail closed). The Go-side check "25 or more texts" stays as a second guard only. A list of 24 or fewer with `truncated: false` and `Cut == 0` is complete.
3. **N is a `Text`, and no field also holds it.** The summary lists the texts of a `Text` and the typed value of an `EditableText` in one `texts` list, and the agent matches a non-obscured field by its value (`_matchesText`), so a field that holds N is a second target for `tap "N"`. The summary **de-duplicates** (`!texts.contains(trimmed)`): a `Text` "Sign In" first and a field holding "Sign In" second would drop the field's entry, and a list built from the de-duplicated texts would not show it. So the agent records **`editable_texts` independently of the de-duplication** (every field that holds the text is recorded whether or not the text is already in `texts`), and N must not be in `editable_texts`. A table row: a `Text` and a field with the same text give **no offer**. Likewise a **raw `RichText`** (not built by a `Text`) is matched by the agent but is not in the summary today, so the unique-substring count would never see it; the same agent change **adds those texts to the summary** (their own key if that is clearer, counted with the rest). The keys the agent builds are its own: a malformed or non-string `editable_texts`, or any key an app could not have made, is read as **absent**.
   **Presence is detected, not assumed.** `VisibleSummaryResult` is a plain struct of slices, so an absent key (an older agent) and an empty list (a newer agent that saw none) decode the same. The new keys are read through pointer fields (or a has-flag), so **absent means no offer** and an empty list means "none". An older agent, an agent that sends no `truncated`, and a malformed answer all give no offer.
   **Version skew: the offer needs a published agent release.** The agent change (`editable_texts` independent of the de-duplication, raw `RichText` texts, `truncated` with the cap and the count) ships in an agent release the owner publishes; the minimum agent version is named here once the release number is decided, and **until that release exists and is the one in the app under test, there is no offer** (nothing breaks: the row is simply not shown). The unknown keys are ignored by older Go readers (`probelink/client.go`), so the change is additive in both directions.
4. **The match mode is the default.** With `defaults.match: loose` (or `--match-loose`) the agent folds more than Studio does, so the substring count above proves nothing: no offer in loose mode. Studio reads the run's `defaults.match` for this (to be confirmed against the config at code time; if it cannot be read, no offer).
5. The label and tooltip fallback (`_findByText`: a `Semantics` label or a `Tooltip` message) is used only when no visible text matches; with N on screen and unique, it is not used, so it adds no second target.

What "visible" means is the agent's: `_isVisible` excludes off-screen, `Offstage`, zero-size and non-top-route widgets, judged **at the moment of the timeout on the current screen**, and the list is de-duplicated by trimmed text, so "exactly one" counts distinct texts, not widgets: two widgets that show the same text count once, and the step would match both. That is the right count for this rule (it proves the text is unique, not the widget); the step's own ordinal or `exactly` form is out of v1 for the same reason.

**The text N is distrusted** (it is data from the app under test) and is used only if all of these hold:
- it is one plain line (`plainSuggestionLine`: no line break, control, hidden, bidirectional or other-width space character) and at most 40 characters (what `VisibleItems` keeps whole);
- it has no `"` and no backslash, and `strconv.Unquote("\"" + N + "\"") == N`;
- `bringsNothingNew(currentLine, newLine)` and the interpolation expression of `replace_line.go` pass: no `${ENV}`, no `<variable>` or `<gen(...)>` form, no `;`, no `#` (a comment) that the original did not hold;
- `sysdialog.ScrubKnown(N) == N`: the masking that the runner applies is only of **known** secrets, so a text the scrub would change is refused. No marker constant is defined and none is relied on;
- it is not X byte for byte (then the text is there and the failure is something else).
Out of v1: a unique near match (prefix, contained text, edit distance), key and id replacement, `long press`, `double tap`, `type`, `see` with `any of`, negated steps. Each needs its own evidence of how often it is right.

## Where the text comes from, end to end
1. `probe_agent`: `visible_summary` gets additive keys: `editable_texts` (recorded independently of the de-duplication), the raw `RichText` texts, `truncated` and the cap; an older agent does not send them and then there is no offer. `probelink` and `runner.VisibleItems` carry them as `Editable *[]string`-style presence-aware fields and `Truncated`. `StepEvent` gets one data field, `Visible VisibleItems`, with **no JSON tag**, set on `StepFailed` only when the error is the runner's step-timeout error (the same value `FailedSelector.Visible` takes). Nothing that decides a verdict reads it; the CLI ignores it. A test pins both.
2. `studio`: when a failed step is turned into a `RunStep`, `triageStep` also gets the visible texts and sets `StepTriage.Replacement` (the new quoted text only, never a whole line) and drops the list (`RunStep` never holds it) and a row reason that names what the screen showed ("the screen shows "Sign In", not "Sign in""). The window shows it as a row with one button.
3. The line that goes into the editor is **built in Go at press time** from the kept text of the run: the original line with only the text between the quotes swapped. The row text is display only.

### `Visible` is no new exposure, and it stays so
The same masked and capped list already reaches Studio's outputs: `stepTimeoutError.Error()` appends it to the failure text (`step_timeout.go`), `toRunStep` sets `rs.Error = ev.Error.Error()`, and so `run_state`, `results` and `ui_state` of the automation endpoint, the Results pane and the exports already carry it (masked with `ScrubKnown`, which covers known secrets only: obscured fields are skipped by the agent, but a password typed into a plain `Text` is not masked unless it is known; nothing here implies more). What the design must **not** do is add a second, raw copy: `StepEvent.Visible` has **no JSON tag**, `toRunStep` never copies it into `RunStep`, and a test pins that (the JSON of `RunStep`, the exports, the log lines and every bridge and automation response never contain the raw list or the `editable_texts`). Studio keeps only the computed replacement text (and, for the suppression rule, a boolean) on the step's triage; the list is dropped when the step event is handled.

## The anchor and the checks: `CheckReplaceStep`
A new bound method, pure like `CheckInsertBefore` and `CheckReplaceLine`: `CheckReplaceStep(file, line, openFile, content)` answers `{ok, line, text}` (the new text of that one line) or a one-line reason. It reads nothing from disk and writes nothing. It refuses when (in this order; the Running read comes first, before the kept-text lookup, as in `CheckInsertBefore`):
1. a run is in progress (`a.track.snapshot().Running`) or the run's kept text for the file is not held;
2. the step has `Depth > 0` (a recipe step: its line is a line of the recipe, not of the calling file; the same refusal and reason as Insert before);
3. the open file is not the file the step ran from (`sameFile`);
4. the editor text differs from the kept text of the run after the same normalisation as Insert before (BOM dropped, CRLF and CR become LF): "the file changed since the run: run again";
5. the line is not exactly the failed step: one step starts there (`stepTarget`), with the event's verb and quoted text, as `see`/`tap` with a text selector, and the line holds nothing else (no flags, no second step, **no trailing comment**: a comment would have to be carried, and v1 refuses instead of guessing);
6. the replacement, recomputed here from the run-state step (never from a window argument), is not allowed by the rules above (unique substring match, fewer than 25 texts, a `Text` and not a field value, default match mode, the text checks), or equals the text already on the line;
7. the text after the swap does not parse to **exactly the same steps at exactly the same lines** (`stepsOf` and `sameSteps` as Replace the line, the line count is unchanged) with the one selector text changed and the verb, flags and shape (`fixProfile`) kept. The profile check is what "same verb class" means: a `tap` stays a `tap`, a `see` stays a `see`. It ignores the selector text, so there is an 8th check: **parse-back**, the parsed step's selector text equals the replacement **exactly** (a text the parser reads differently from what Go built is refused).

## The editor (window)
- The window applies the edit only when the check said ok **and** the editor is still what was checked: at the click it captures the open path, `model.getVersionId()` and the text; after the Go answer it applies only if all three are unchanged (one model, never `setModel`), as Insert before does.
- One edit in **one undo stop** (`pushUndoStop` before and after), replacing the one line; the caret goes to the line. The line ending of the line is kept (the swap does not touch it). **Nothing is saved**: Save stays the person's action. Nothing is run, and no "try it" step: the person looks, then presses Run.
- The button is disabled between `run:started` and `run:finished` (`runGoing`), the handler refuses while running, and Go refuses while the tracker is running (check 1): three independent layers.
- Line count does not change, so the step marks and row line numbers stay valid; the marks of the replaced step are cleared and the row says "edited". After the swap the file differs from the run's text, so every other offer of that run (this one, Insert before, the AI card) refuses with "the file changed since the run: run again" until the next run, the same staleness rule. An **Undo** brings the run's text back and the button works again.
- The row sits where the rule rows are, with its own label so it is never confused with the AI card's **Replace the line** (see the open questions).

## The method and its entry
`CheckReplaceStep` in `studio/bound_methods.json`: category `ui`, callers `window` and `bridge`, `touches` none, `confirm` `none`, `does` "Checks whether the rule-based replacement for a failed step may be put into the editor, and returns the new text of that line; reads Studio's kept text of the last run; changes nothing." Not in the automation method list (the guard test checks it). The guard tests derive `touches` and fail if it reaches a file, the keychain, the network or a device, so "pure" is enforced, not claimed. No AI, no provider, no network. A bridge caller can ask what the kept text says about a line, which is no more than `run_state` already tells it. `asks` is not used: nothing here needs a person's answer in Go, the person's press is the answer, and the check changes nothing.

## Tests to write with the code (a mutant per test)
- `runner`: the field is set for a timeout and empty for every other failure and for a pass; the CLI's reports are byte-identical with and without it.
- `triage`: a table of the replacement rule: one fold match gives it; none, two, a byte-equal match, an id selector, a text with a quote, backslash, control, hidden or bidirectional character, `${X}`, `<x>`, `;` or `#`, a text `ScrubKnown` would change, a text over 40 characters and a loose match mode give none; **substring ambiguity** (`Sign In` with `Sign In with Google`, `Delete` with `DELETE ALL`) gives none; a snapshot of exactly 25 texts gives none and 24 gives the offer; `Cut > 0` gives none (a 60-character text that contains N); `truncated: true` and an absent `truncated` give none; a candidate that is also in `editable_texts`, **a `Text` and a field with the same text**, a raw `RichText` that also contains N, an agent that reports no `editable_texts` (absent, not empty), and a malformed `editable_texts` give none; an empty `editable_texts` with the other keys present gives the offer. A mutant for each rule (drop the substring count, drop the 25 cap, drop the `Cut` check, drop the `truncated` check, treat absent as empty, drop the editable check, drop the loose-mode check, drop the scrub check). The agent has its own unit tests for the three new facts (a field and a `Text` with the same text, a raw `RichText`, `truncated` at and below the cap).
- `CheckReplaceStep` table: one case per refusal above (running, no kept text, Depth > 0, another file, a changed file by one character and by an edit above that shifts an identical step, an unsaved edit, a line with a comment, a line with another step, a replacement that fails `Unquote`, a result that parses to different steps or lines, a parse-back whose selector text differs) and the accepted case; a mutant per refusal; two identical steps with an edit above must be refused (the wrong-step case); a CRLF, a mixed-endings and a BOM file are accepted after normalisation; **a failed step inside `repeat` or `retry`** (one event per attempt, the kept text equal: accepted once, for the line) and **a failure in a hook step** (refused or handled as the other Depth rules say) and **a non-timeout failure** (no `Visible`, no offer) each have a case.
- `Visible` stays inside: the JSON of `RunStep`, the exports and the automation responses never hold the raw list or `editable_texts` (a test that fires a failed event with a list and a sentinel text and greps every output).
- The guard tests: the entry is present and derived as pure.
- Playwright, no device, a seeded failed run that carries visible texts: the row appears only when the rule gives a replacement; one press swaps the quoted text and one undo restores it, and the button works again; a second press is refused; an edit first (above or on the line) is refused; another open file is refused; a press during a run is refused (disabled) and a press that races the click (the editor changed between the click and the answer) applies nothing; hostile on-screen texts (markup, a quote, a backslash, a bidirectional character) show as text and give no row or an inert one; with the AI card on the same step, after this edit the AI card's **Replace the line** refuses, and the other way round (this holds by design only after the prerequisite change to `CheckReplaceLine`, and the spec is written with it); a CRLF file; marks and counts stay valid; no Save call is made (a recorded route proves it).

## Out of scope
Recipe steps (Depth > 0: needs the real file on the event, a separate change), a non-default match mode, ids and keys, other verbs, fuzzy matching, running after the edit, saving, any model, any new network call, and anything that changes the runner's verdicts.

## Questions for the owner (recommended answers; treated as decided unless the owner objects)
1. **Label.** Distinct from the AI card's "Replace the line": the row's button says `Use "Sign In"` (what it does, with the text).
2. **The wait fix when a replacement is offered.** If the screen showed "Sign In" at the timeout, the text is not late, it is spelled differently, and `wait until "Sign in" appears` would time out again. Suppress the wait fix **only when the replacement is actually offered**, not when it was refused (substring ambiguity, the 25-text cap, a field value, loose mode): then the wait row stays as it is today. This changes the Insert before row (its table gets cases for both).
3. **Fold only, or also a unique near match?** v1 is fold-only; decide again with real counts of how often the offer appears.
4. **A Re-run card after the swap?** Yes, through the existing line-count rule (the count is unchanged); the click never runs anything.
5. **A trailing comment on the line.** Ship the refusal; carry the comment only if the refusal is seen to be common.

## Further Studio hardening, ranked by value for the effort
Each has a number to hit, so a review can say done or not done.
1. **Windows vet is in no gate.** `scripts/ci-local.sh` builds `./cmd/...` for Windows but never vets `./studio/...`; #825 sat on main unnoticed. Add `GOOS=windows go vet ./studio/...` (and `GOOS=linux`) to `ci-local.sh` and `studio-ci.yml`. Target: 0 packages failing on all three OSes, and a deliberately broken `Setpgid` line in a scratch branch turns the step red. Cost: very small.
2. **Save in place is not atomic.** `WriteFile` truncates and rewrites the person's file; a crash or a full disk mid-write leaves a truncated file (the results export already writes to a temp file and renames it, `TestExportReplacesAnExistingFileAtomically`). Target: a writer that fails after N bytes leaves the original byte-identical (a test with a failing writer seam, N in {0, 1, half, all-1}); the file mode is kept; a link in the place of the file is still refused. Cost: small.
3. **`WriteFile` can write a `.probe` file under `.git` or any hidden folder inside the workspace, and has no size cap.** Target: a table of 10 hidden or VCS paths (`.git/`, `.hg/`, `.svn/`, `node_modules/` as the person decides) refused with a sentence, and a cap equal to Save-as's 1 MiB or an owner-chosen one; 0 writes under those names in the test. Cost: small; needs the owner to choose the list.
4. **The browser suite has one known load flake** (`ui-03`, a real device listing under load) and the web suite is the gate for the window. Target: 0 failures in 20 consecutive full runs on a loaded machine (a loop in `ci-local`), by answering the device listing by hand in the specs that do not test it. Cost: small.
5. **Recipe steps have no anchor** (`Depth > 0` is refused by Insert before, Replace the line and this design). Add `StepFile` to the step event. Target: Insert before and the new Replace work for a step inside a recipe, with the same table of refusals; the kept text of recipe files is used for the first time. Cost: medium, touches the runner's event.
6. **`studio/frontend/src/main.ts` is 2,637 lines** with the shortcuts, save, record, run, connect and chat in one file; every change in it risks the others (the Save-as, Insert and shortcut work each had to read all of it). Target: no behaviour change, the full web suite unchanged, and the file under 1,800 lines by moving the Save/Save-as, Record and the shortcut handler into their own modules with node tests. Cost: medium, low risk if done one module a PR.
7. **Studio workflows are off (#402, an owner setting) and the scripts replace them locally.** Target (owner): `studio-ci.yml` and the e2e workflows enabled, and `scripts/ci-local.sh` parity checked by a test that the same steps exist in both. Owner action, not mine.

## Order of work
1. Atomic `WriteFile`, then `WriteFile` hidden-folder refusal and the 1 MiB cap (the hardening queue).
2. The AI-card hardening PR: `CheckReplaceLine` gets the Running, `Depth > 0` and kept-text checks (the prerequisite above).
3. The agent change (an agent task with unit tests, by the session the business session assigns): `editable_texts` independent of the de-duplication, raw `RichText` texts, `truncated`, the cap and the count. It needs a published agent release.
4. The N8 code, after the design is accepted and 1 to 3 are in.

## Follow-up: glyph characters (code of this note)
The agent's text matcher also matches an `Icon`'s glyph (a private-use character) by a text selector, and the summary leaves Icon glyphs out of `rich_texts`: a replacement text that holds one could be a `Text` next to an `Icon` that shows the same glyph, where the summary shows one match and the agent matches two. So a replacement text with a private-use character, U+FFFC, U+FFFD or any unassigned code point is refused by its own rule (asked before the "plain line" rule, so it is a rule of its own and not only a case of it), and so is a text with no letter or digit.

## Follow-up: the failed text already on screen (review of the code)
The rule must also give no offer when the failed text is already visible, in any of the three lists and also inside a longer text (the agent's own match is a case-sensitive substring): then the step did not time out for want of it (a widget that cannot be hit, or a hidden one), and a step with the other spelling would act on another widget. "Sign in" with `Sign in` and `Sign In` on screen, or with `Sign In` and `Sign in with Google`, are the two cases. The match mode is also refused when the config value is anything but the default in any letter case, and when the process-wide loose switch the CLI sets is on.
